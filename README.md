# Moneybox

PWA для учёта ежедневных трат в стиле iOS (Liquid Glass): дневной лимит с переносом остатка,
регулярные платежи, общий бюджет семьи по ID.

## Как считается дневной лимит

1. **Свободно на период** = ежемесячные доходы + разовые доходы этого периода − активные регулярные платежи.
2. **База в день** = свободно ÷ количество дней периода (период начинается в «день зарплаты», настройка в «Семье»).
3. **Лимит дня** = база + перенос со вчера. Всё, что не потрачено за день, добавляется к лимиту следующего дня.
4. Перерасход — на выбор: вычитается из завтрашнего лимита целиком или распределяется по оставшимся дням периода.
5. Если учёт начат в середине периода, бюджет считается только на оставшиеся дни (пропорционально).

Логика — `src/lib/budget.js`, тесты — `npm test`.

## Семья

У каждого пользователя есть семья (сначала — личная). В разделе «Семья» есть **ID семьи** (10 символов,
`XXXXX-XXXXX`). Другой человек вводит его в «Присоединиться по ID семьи» — и у вас общие траты, доходы,
регулярные платежи и один дневной лимит. Если присоединяющийся был в своей семье один, его данные
переносятся в новую семью. Владелец может исключить участника или сменить ID.

## Бэкенд

Supabase-проект **encore** (общий для всех приложений, один аккаунт на все приложения).
Уже существующие пользователи просто входят своей почтой и паролем — регистрироваться заново не нужно.

- Схема `moneybox` (таблицы `families`, `members`, `incomes`, `recurring`, `recurring_paid`, `expenses`) с RLS.
- Клиент работает через security-invoker представления `public.mb_*` и RPC `public.mb_*`,
  поэтому схему `moneybox` не нужно добавлять в Exposed schemas.
- Общий профиль — `public.profiles`.
- Миграция: `supabase/migrations/20261107210000_moneybox.sql`.

## Запуск

```bash
npm install
npm run dev      # разработка
npm test         # тесты расчёта бюджета
npm run build    # сборка в dist/
```

URL и publishable key Supabase лежат в `src/config.js` (их можно переопределить через
`VITE_SUPABASE_URL` / `VITE_SUPABASE_KEY`).

## Деплой

`.github/workflows/deploy.yml` собирает и публикует `dist/` на GitHub Pages при пуше в `main`
(включите Settings → Pages → Source: GitHub Actions). Сборка использует относительные пути, поэтому
работает и в подпапке, и на своём домене.

Чтобы ссылки из писем (подтверждение почты, сброс пароля) вели в приложение, добавьте его адрес в
Supabase → Authentication → URL Configuration → Redirect URLs.

На iPhone: откройте сайт в Safari → «Поделиться» → «На экран «Домой»».
